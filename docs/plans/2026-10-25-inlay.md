# V-Carve Inlay Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One command, "V-Carve Inlay", turns a design sketch into a pocket Job (v1 pair) and a plug Job (new V-Carve Plug op plus v1 clearance), with step-down passes, an optional ridge pass for tipped bits, and a fit test proving that the parts seat.

**Architecture:**
- The V-Carve Flat op becomes the base of a small proxy interface (`regions`, `levels`, `floor`, `wall_loops`, `extra_paths`, `end_mill_error`). Its `opExecute` loops over levels. The clearance op calls the same interface on whatever op it links, so it never needs to know which kind it is.
- The plug op (`op_plug.py`) subclasses V-Carve Flat. It overrides that interface: it mirrors the pocket op's sketches, carves the complement at the virtual surface `Z_v`, clips floors to the plug boundary, and adds the ridge pass.
- `inlay.py` builds both Jobs headless. The GUI adds a command with a dialog on top of it.

**Tech Stack:** As v1: FreeCAD 1.0.2 / 1.1.4 / 26.3rc2, Part, Path (Voronoi, Area), numpy, PySide; pytest for `geom.py`; `freecadcmd` + `unittest` under `tests/fc/`.

**Spec:** `docs/specs/2026-10-25-inlay-design.md`

## Global Constraints

- FreeCAD 1.0.2, 1.1.4 and 26.3rc2; the full suite runs before every commit:
  `FREECAD_APPRUNS=<1.1.4 AppRun>:<1.1.1 AppImage>:<1.0.2 AppRun>:<26.3rc2 AppRun> python -m pytest -q` (the paths are given to each implementer).
- Every new source file starts with `# SPDX-License-Identifier: LGPL-2.1-or-later`. No F-Engrave code. Do not patch CAM files.
- Input is sketches only. The plug op takes its sketches from the pocket op (`PocketOp`), never from its own Base.
- Notation: t = tan(half angle), r_t = tip radius, P = pocket depth (the pocket op's capped Flat Depth), G = `GlueGap`, S = `SurfaceGap`, `start = P − G`, `Z_v = plug StartDepth − start`.
- Plug defaults: `GlueGap` 0.2 mm, `SurfaceGap` 1.5 mm, `RidgePass` True, `PlugBoundary` `["Margin", "Stock"]` = "Margin", `PlugMargin` 10 mm, `MirrorAxis` `["X", "Y"]` = "X". `PlugStartDepth` is read-only and equals `start`.
- Defaults that fit the bit: `P = min(3, 0.6·cone)`, `G = 0.2`, `S = min(1.5, cone − (P − G))`.
- Errors (no path): G ≤ 0 or G ≥ P; `P − G + S > cone height` (message names the excess in mm); plug V-bit differs from the pocket V-bit (diameter, angle, tip diameter); pocket op Flat Depth is 0; `PlugMargin <` end-mill diameter (raised by the clearance op). Warnings: plug stock thinner than `P − G + S`; in Stock mode, stock XY does not cover the design.
- `StepDown` comes from `PathOp.FeatureStepDown` on all four op types. `StepDown ≤ 0` or `≥` final depth means one pass. The Inlay command sets `StepDown = 1.5 mm` on its four ops. It clears the setup-sheet expression first, otherwise the expression `OpToolDiameter` overwrites the value.
- With `StepDown = 0`, v1 ops produce **identical** paths to today. The existing tests keep passing unchanged.
- No GUI dialogs from op code; problems go to `Path.Log` and name the op or sketch.

## Review Focus

1. **Pocket op with Flat Depth 0** linked as `PocketOp`: P is undefined. The plug op logs an error naming the pocket op and makes no path. (Task 4: `test_pocket_without_flat_depth`)
2. **The plug Job's V-bit is edited** (diameter or tip) after creation: an error on the next recompute, no path. (Task 4: `test_different_vbit`)
3. **Letters thinner than `start·t` and letters closer than the tip diameter** (small text): no exception escapes, and the fit holds on the measured lines. (Task 5: the `THIN` fixture)
4. **The design sketch is edited after the inlay was made:** the plug follows on recompute without re-running the command. (Task 6: `test_sketch_edit_updates_plug`)
5. **v1 documents restored without `StepDown`:** paths are unchanged. **The 1.5 mm the command sets must survive a recompute**, i.e. no expression is left on it. (Task 2: `test_restored_without_stepdown`; Task 6: `test_stepdown_set`)

### Task 2: Levels and step-down for V-Carve Flat; clearance through the proxy

**Files:**
- Modify: `vcarve_flat/op_vcarve.py`, `vcarve_flat/op_clearance.py`
- Test: `tests/fc/test_op_vcarve.py`, `tests/fc/test_op_clearance.py`

**Interfaces:**
- Consumes: `pass_depths`, `carve_polylines(min_depth=)` (Task 1).
- Produces in `op_vcarve.py`:
  - `CarveSetup` gains `flat: bool` and `min_depth: float = 0.0`. `carve_setup(obj)` sets `flat = FlatDepth > 0`. Every `cs.r_flat > 0` test becomes `cs.flat`.
  - Methods on `ObjectVCarveFlat` (the proxy interface; each takes `obj` first):
    - `regions(obj) -> list[(label, faces | SketchError)]`: returns `region_sets(obj)`.
    - `levels(obj) -> list[CarveSetup]`, shallowest first: one `CarveSetup` per `pass_depths(cs.depth, obj.StepDown.Value)` with that depth and `r_flat = flat_radius(vbit, d)` if flat, else 0. `capped` is set only on the last level.
    - `floor(obj, cs, faces) -> list[Face]`: `offset_faces(faces, -cs.r_flat)`. This is the V-bit tool-centre floor of the level, which both the end mill and the rest pocket use.
    - `wall_loops(obj, cs, face) -> list[np.ndarray]`: `flat_boundary_loops(face, cs.vbit, cs.z_top, cs.depth, ...)`.
    - `extra_paths(obj) -> list[np.ndarray]`: V-bit paths cut after all levels; `[]` here.
    - `end_mill_error(obj, diameter) -> str | None`: `None` here.
  - `opFeatures` adds `PathOp.FeatureStepDown`. `opExecute` and `_carve`/`_rest_pocket` take a `CarveSetup` per level and call the methods above through `self`. The output is ordered level by level, each level as today (rest, medial, loops via `order_paths`), and then `extra_paths`.
  - `opUpdateDepths`: `OpFinalDepth = levels[-1].z_top − levels[-1].depth`.
- In `op_clearance.py`: `opFeatures` adds `FeatureStepDown`. `opExecute` and `opUpdateDepths` use `link.Proxy.regions/levels/floor` and pocket each level at `cs.z_top − cs.depth`, shallowest first. The `FlatDepth == 0` early return becomes `not levels[-1].flat`. Before pocketing, if `link.Proxy.end_mill_error(link, diameter)` returns a message, log it as an error and return.
- **The clearance op's own `StepDown` is not used:** its levels come from the linked op, so both tools stop at the same depths. Hide it with `setEditorMode("StepDown", 2)` and say so in the README (Task 8).
- **FlatDepth = 0 with step-down (my call):** the intermediate levels cut only the medial axis clamped at `d_k`; no floor is cleared.

The tooltips state their reference ("below the plug board's top", "gap between plug top and pocket floor when seated").
  - It keeps v1's carving fields (Discretize, Colinear, StepLength, Tolerance, RestScallop). `FlatDepth` and `BaseShapes` are hidden (editor mode 2) and unused.
- `opFeatures`: as Flat, minus `FeatureBaseEdges`, plus `FeatureStepDown`. `opRejectAddBase` returns True.
- Geometry, per execute. `L` = the union of the faces of all `region_sets(PocketOp)` entries (the error entries are logged by the pocket op, so skip them), mirrored with `mirror_faces` about the centre of L's joint bbox along `MirrorAxis`:
  - `B` (floor limit): Margin is `area_offset(L, S·t + PlugMargin)`. Stock is the plug Job's stock XY bbox as a face, grown by the end-mill radius `rest_clearance(find_clearance_op(obj)).x`.
  - `C_v = subtract(area_offset(B, 2·vbit.radius + 1), L)`. Its outer edge lies so far out that its medial axis there is all floor, and its wall loops lie outside `B`.
  - `regions(obj) -> [("<pocket op label> plug", C_v)]`, or `[(label, SketchError)]` when the pocket has no faces.
  - `levels(obj)`: for `s in pass_depths(start + S, StepDown)`, `d = s − start`, `CarveSetup(vbit, z_top=Z_v, depth=d, r_flat=flat_radius(vbit, d), capped=False, flat=True, min_depth=-start)`. `r_flat` may be negative.
  - `floor(obj, cs, faces) = intersect(area_offset(faces, -cs.r_flat), B)`.
  - `wall_loops(obj, cs, face) = inside_loops(<wires of area_offset([face], -cs.r_flat) at z_top − depth, simplified>, B)`.
  - `extra_paths(obj)`: if `RidgePass`, `ridge_polylines(f, vbit, Z_v, start, ...)` for each face of L, else `[]`.
  - `end_mill_error(obj, d)`: in Margin mode, if `PlugMargin < d`, a message naming both values.
- Checks at the start of `opExecute`, each logged as an error that names the plug op, followed by a return:
  - `PocketOp` is missing, or is not an `ObjectVCarveFlat` that is not itself a plug.
  - The pocket op has no V-bit TC, or its `FlatDepth` is 0.
  - The plug V-bit differs from the pocket V-bit.
  - `plug_errors(...)`.
- Warnings: plug Job stock `ZLength < start + S`; Stock mode with the stock XY not containing L's bbox.
- `levels(obj)` returns `[]` while the checks fail (no valid pocket op yet); the base `opUpdateDepths` then leaves `OpFinalDepth` alone.
- `opUpdateDepths` sets `PlugStartDepth = start` (when the pocket op is valid) in addition to the base behaviour.
- `opOnChanged`: a change of `PocketOp` touches nothing extra. FreeCAD's link dependency recomputes the plug when the pocket op or its sketches change. Verify this in the test below.

### Task 5: Fit test

**Files:**
- Create: `tests/fc/fit.py` (helpers), `tests/fc/test_fit.py`

**Interfaces:**
- Consumes: the ops from Tasks 2 and 4 and the setup from `test_op_plug.py` (move the setup into a shared function `make_inlay(doc, loops, circles, tip, stepdown, ridge)` in `fit.py` if both tests need it).
- `cut_height(paths_by_tool, points) -> np.ndarray`: the lowest Z the tools reach at each XY point.
  - `paths_by_tool` is `[(G1 polylines resampled to ≤ 0.05 mm, tool profile)]`.
  - V-bit profile: at horizontal distance ρ from a path point at z_c, the tool's lower surface is `z_c + max(0, ρ − r_t)/t` for ρ ≤ R, and ∞ beyond R.
  - End mill: `z_c` for ρ ≤ R_e.
  - Points no tool reaches are at 0 (the uncut top).
- Seated gap at a board point q: `gap(q) = (−P + G + s(q')) − z_pocket(q)`.
  - `q'` is q mirrored with the plug's axis and centre.
  - `s(q') = −z_plug(q')` is the plug depth of its cut surface.
  - Negative means the parts collide.

- [ ] **Step 1: Write the tests** on the fixture `RECT` + RING + a 3 mm bar + `THIN` (a 0.8 mm bar, and two letters 0.3 mm apart). Sample 5 horizontal lines (through the wide area, the bar, the counter and the thin features), at 0.05 mm spacing, within the design's bbox:
  - `test_fit_sharp` (`TipDiameter = 0`): `gap ≥ -0.02` everywhere. `|gap − G| ≤ 0.02` where both sides are at their floor/top (wide areas). `gap ≤ 0.02` on wall points (where the pocket z is strictly between 0 and −P).
  - `test_fit_tipped_ridge` (`TipDiameter = 1`, ridge on): the same assertions, excluding points within `2·r_t` of a sharp corner of the design. Those are the documented corner effects; the fixture's lines avoid most of them.
  - `test_fit_tipped_no_ridge`: on the bar line the minimum gap is `< -0.5·r_t/t`, which proves that the ridge pass is needed.
  - `test_fit_stepdown`: `test_fit_sharp` with `StepDown = 1` on all four ops.
